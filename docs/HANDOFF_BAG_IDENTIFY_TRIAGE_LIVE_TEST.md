Important findings at handoff creation:

1. Map triage currently calls the older `evaluateWithAppraisal`/value-tier export and starter-price fallback, rather than the new batch assessor. It must not invent a second bag-only pricing model.
2. `decideDrop` defaults unmatched `unknown` verdicts to dropping unless `--keep-unknown` is set. That does not satisfy the new Review/unknown semantics. Make unknown retention an invariant in the integrated flow, not a flag the user has to remember.
3. The default fast path assesses all identified gear; the careful path normally assesses only gear identified during that run, unless widened by `--include-identified`. Establish one explicit batch scope and consistent behavior across the app, CLI and hotkey.
4. The fast path verifies the first drop, then sends remaining pickup/ground clicks as a burst with only an end probe. It does not establish each intermediate item's identity and receipt. First/last success is insufficient evidence that every intended item was safely dropped.
5. `mergeAdjacentDuplicates` can merge touching identical fingerprints; physical neighboring copies must not be collapsed merely because their text matches. Reuse complete-footprint reasoning from the new capture pipeline.
6. Older notes contain August live results and differing descriptions of fast/careful behavior. Treat them as historical evidence, not proof that today's integrated pipeline is ready. The legacy command labeled dry-run still starts the host and reads the live game; it is not an offline test.
7. The current map runner/SortHarness calls the native host directly without the application's `GameInputController`/emergency-monitor wiring. Numpad stop/pause is checked at JavaScript checkpoints, while fast native bursts are unchunked and do not pass the host's per-click `requireForeground` option. Verify and repair actual stop/focus enforcement across CLI, daemon and packaged execution; inherited documentation is not proof of cancellation during a burst.
8. Current journal writes are mostly post-phase summaries and swallow write failures; they do not supply durable per-item restart reconciliation. Identification also does not fully pin before/after physical identity or reconcile actual scroll-stack decrements. These are required integration work, not already-proven guarantees.
9. Unknown flags and invalid numeric arguments are insufficiently rejected in the old runner. `npm run map:calibrate` performs real bag moves even without `--run`. Treat it as live mutation, never as an offline readiness check.

## Required workflow and shared decision policy

1. **Capture the complete bag.** Use verified 12×5 inventory geometry and full coverage, not only bright sprite detections. Persist every physical item, coordinates/footprint, exact advanced text and unread/ambiguous cells. Keep duplicate copies distinct. Record the initial batch and which items are eligible equipment; currency, Wisdom scrolls, gems, waystones/tablets, quest items and other unsupported special classes are protected. Show excluded unidentified objects explicitly rather than silently spending scrolls on them. Equipped items and other containers are outside this bag test.
2. **Identify eligible unidentified equipment.** Locate and verify the actual Scroll of Wisdom stack and count; the existing first version expects the very top-left bag cell `(row 0, column 0)`. Use enough scrolls for physical items, not occupied cells. Preserve before/after text and a stable physical item ID through identification; the fingerprint can legitimately change when the item becomes identified. Already identified equipment does not consume a scroll. Handle missing/short/depleted scroll stacks, missed arming/clicks, exhausted shift-use mode, delayed clipboard, wrong-item targeting and cursor-held items with bounded verified recovery. Re-copy after identification; a click is not proof of success.
3. **Assess the captured post-identification batch.** Reuse the shared model, exact league profile, knowledge snapshot, weights, overrides and price-evidence rules used for stash assessment. Use **Forbidden Rites normal trade**, unless the user explicitly selects another league. Capture and ordinary assessment make zero market calls. Preserve original/pre-identification captures, assessment versions and action receipts; support offline reassessment without another scan or identification.
4. **Keep useful items.** Shared Keep/useful-now, Craft candidate, explicit Keep feedback, and valid fresh price-confirmed evidence all protect an item. Relevant T1/T2 combinations, life/ES/resistances, damage/speed, coherent jewels, magic/normal bases, uniques and special effects must behave consistently with the rest of the app. A score is not a chaos price. Review feedback and any missing/unknown evidence also mean retain, not discard.
5. **Use optional pricing selectively.** Reuse `PriceFeedService`, comparable matching, league/patch caches and the persisted queue; default to at most ten distinct searches, with bounded listing fetches and visible counters. Throttle/cancel/budget pauses must not change an item into junk or block the local ledger. The price-confirmed keep route still needs fresh adequate evidence strictly above `max(1, configured threshold)` chaos. No comparables, expired/unavailable evidence or failing that price threshold does not prove an item should be dropped. Do not send every bag item to trade or use generic starter prices as disposal authority.
6. **Plan drops from positive evidence.** Only an eligible, identified physical item in this captured test batch with the shared Low-priority outcome, adequate known coverage, no Keep/Review override, no useful/crafting/special opportunity and no protecting market evidence can enter the drop preview. Do not invert `status: stay`, an unmapped stash destination, a zero score, a missing price or absence from the shortlist into drop permission. A local low-priority outcome is a heuristic disposal choice, not proof of zero market value. Present the reason and uncertainty for every kept/review/drop item before live execution.
7. **Revalidate and drop one item at a time.** Before pickup, verify the current map context, exact current item text/state and physical position, and current decision/profile. Saved coordinates alone are insufficient. Prove the intended item was picked up, released onto valid map ground, and is no longer held on the cursor before another pickup. Reuse recovery helpers only after testing their assumptions; empty clipboard text is not automatically an empty cell. Retain observable receipts and report uncertainty honestly if ground-label or cursor evidence is unavailable. On ambiguity, stop without attempting another item or blind recovery click.
8. **Resume safely.** Checkpoint before mutations and after verified outcomes. A crash after identification, pickup, drop or verification must leave enough information to reconcile current reality. Never identify or drop an already completed item again, silently retry an uncertain mutation, or apply a saved result to another identical neighbor. Identification, assessment, optional pricing and dropping must be independently resumable.

Protect the existing emergency stop, pause behavior, process/window allowlisting, generated-input trace, calibration checks and input release on interruption. Validate arguments and saved files before starting a host or sending input. Prove that the player is in the intended map context; absence of the stash panel alone is not sufficient. Recheck relevant modal/loading/death/focus conditions during execution. Ground coordinates must be current, within the game client and outside inventory, stash, vendor, trade and other UI.

Test that cancellation stops native execution itself and releases held modifiers, not just the next JavaScript phase. Never perform an automatic recovery click after emergency stop. A journal failure before a pending mutation must prevent that mutation. An unknown cursor state after an identification abort must block the drop phase. Do not manufacture dropped counts from planned queue length or restore an unknown-size held item into an unverified one-cell gap.

Disable compaction during initial identification/drop validation. If compaction remains available afterward, test it separately against current full-bag identities, protected items and cursor recovery; success cannot be inferred only from equal occupied-cell counts. Do not lower learned timing floors or retain unverified bulk drops merely to improve speed.

## Test and fault-injection matrix

Build meaningful deterministic tests and screenshot/input replays around the real adapter boundaries, covering:

- Empty and full bags; mixed sizes; gaps and dim items; multi-cell gear; touching identical copies; repeated names with different rolls; invalid geometry; partial coverage; sprite splits/merges; unreadable, stale or cross-item clipboard results.
- No/wrong/empty/short Wisdom stack; exactly one remaining scroll; more occupied cells than items; already identified equipment; uniques; unsupported non-gear; retry limits; identifier/fingerprint transition; item moved during identification; held item after a misfire.
- Parity with shared stash decisions for relevant T1/T2 and multiple T2, weak triple resistance, chaos resistance, hybrid groups, magic/normal crafting bases, full-affix good items, restrictions, recognized/unknown uniques, unfamiliar modifiers, capacity exceptions and conflicting tier/range evidence. - Ground click refusal; town/hideout; stash/vendor/trade/modal overlays; wrong focus; map transitions, death/disconnect; pickup failure; cursor still holding an item; a middle drop failing while first/last probes succeed; changed source identity; stop/pause and worker termination at every mutation boundary.
